# Committing-to-git diagnostic migration inventory

This inventory accompanies the accepted [recovery implementation plan](../plans/2026-09-21-committing-to-git-recovery.md). It records the implemented producer and consumer boundaries for review. It was consolidated during implementation, not before the first migration slice. No intermediate package is a release candidate until the complete migration and qualification pass.

## Shared boundary and direct cutover

`src/committing-to-git/diagnostics/diagnosticContract.js` owns common result construction, validation, warning construction, bounded projection, JSON/text encoding, and encoding fallback. `workflowDiagnosticError.js` owns expected diagnostic identity, native causes, and exception normalization. `cli/commandExecution.js` owns execution-once and delivery-once. Operation-specific state comes from the operation or the validated transaction observer, never a raw dispatcher read. The executable field definition is the contract authority; [public diagnostics](../../skills/committing-to-git/references/diagnostics.md) explains its semantics and bounds.

The former command-specific error classes, envelopes, text renderers, and exit mappings are removed. All controlled callers migrate directly. Persisted transaction version 4, semantic content version 3, check receipts, publication artifacts, and report-domain artifacts retain their existing schemas. A durable report-detail page now contains the current public result; its existing wrapper remains unchanged. No old-result reader or transaction migration is provided.

Common result fields are always present. Null means not applicable or not supplied; `unknown` means the owning operation cannot assert the effect. Command payload fields are extensions, not substitutes for reserved identity, state, authorization, recovery, or exit fields. Successful warnings retain exit 0. The seven dispositions map to exits 0 through 6 as documented; known commits survive later failures, and uncertainty never becomes absence. Recovery argument vectors preserve exact operands or are omitted on normalization failure, never repaired by truncating paths.

Stable codes within a producer family share its construction boundary; unknown exceptions share the sanitized internal-failure family. Additional shared producers are finite: `evidence/evidenceVocabulary.js` owns policy/basis/note diagnostics; `selection/changeSelection.js` owns selector grammar and unmatched explicit values; `signature/signaturePreflight.js` owns SSH trust prerequisites; `transaction/transactionWorkspace.js` owns unsupported persisted-version rejection and transaction admission; canonical message ownership lives in `message/canonicalMessageState.js`. Their unexpected exceptions use the same internal family without promoting arbitrary exception strings to public advice. The shared fallback preserves known OIDs and effects even when details are cyclic, hostile, oversized, or unencodable. Output delivery failure has one sanitized stderr notice and never writes a second result or replays the operation.

The registry coverage test compares an independently enumerated packaged route set with `COMMAND_ARGUMENTS`. Every route is executed from the delivered plugin bundle for duplicate/syntax rejection and JSON/text equivalence. Domain suites exercise successful and non-successful operation-specific behavior. Package-only recovery tests cover the original four journeys plus completed-commit verification failure. Fresh agent trials separately establish actual public-guidance usability, including unknown mutation recovery and terminal failure; they do not replace deterministic or independent review.

## Evidence and limitations

The baseline fresh agent completed all four original endpoints. Its observed shortcomings were indirect lineage-shape discovery and the missing direct multiline input path; this change must not be described as repairing four previously failing endpoints. Baseline helper SHA-256: `53a7f5319fb723aed864815389acd4201ee9280779b884bc80a517f66558cfb6`.

Adversarial contract tests independently assert protected-field ownership, exact recovery arguments, bounded warning/detail omissions, cyclic/accessor/proxy handling, output delivery failure, known mutation preservation and exact JSON Pointers. Whole-repository verification includes imported/evaluation tooling but does not establish behavioral qualification of every authored skill. Windows-only filesystem skips and absent other-host executions remain explicitly untested coverage, not passing tests. Native HISEW receipts and the retained review/trial records are required before production readiness is claimed.
