# Phase 5: Naming execution and honest trigger evidence

Parent: [master plan](../2026-10-03-evaluation-modernization.md). Slice: SLICE-006. Ledger: KEEP-018, KEEP-019, KEEP-033 through KEEP-035. Decisions: DEC-002 through DEC-006, DEC-010.

## Entry and outcome

Use the already-migrated naming source project and a qualified shared execution boundary. Deliver a naming campaign that retains the current cases, calibration selection and prescribed follow-ups but obtains every new model launch through the shared Hadden runtime. Keep lexical checks, semantic grades, classifier diagnostics and real host activation as distinct evidence types.

The baseline runner is not an assured provider adapter: it invokes an operator-local Antigravity executable, evaluates responses with keyword heuristics, and asks the model to select a skill for trigger diagnostics. Preserving those observations does not require preserving that launch bypass. Do not describe historical scores as certified semantic correctness or actual client activation.

## Preserved experiment and conversation

Keep calibration IDs `1, 2, 4, 6, 7`, two arms and one repetition: ten sessions per selected model profile. Preserve the existing labels through the compiled contract; a consumer's generic variant label must not rename an experimental arm. Record the current configured model strings as configuration, not verified availability or a quality ranking. A replacement model/profile changes experiment identity and needs its own preparation.

Case 4 first critiques broad bucket nouns and then receives the exact senior-lead pushback. Case 7 first critiques a negative Boolean and then receives the exact legacy-database pushback. The Hadden scripted controller supplies those committed turns after the appropriate response. A single prompt concatenating future turns is not equivalent. Reject a provider/profile that cannot sustain the required protocol; report partial portable coverage separately.

Keep the no-skill treatment free of injected skill content while ensuring the same allowed capability envelope across arms. Capture the complete generated skill bundle, including references and the checker/policy asset, for the skill treatment. A fake provider can prove input selection and transcript integrity; it cannot prove the agent used the checker or understood a reference.

## Grading and trigger boundaries

The Python checker diagnoses lexical/policy issues. Its `semantic_certified: false` field is an intentional contract. The legacy keyword grader is a reproducible diagnostic with known false-positive/negative possibilities. Neither replaces reviewed semantic judgments against assertions and expected output. Retain historical scores unchanged; a new grader records a new version and derived result, never overwrites the old aggregate.

Preserve assertion text during structural migration even where it encodes a local convention or an overbroad standards claim. Log suspected assertion defects for a separate source-grounded content revision with new case identity and reviewed comparison limits. Do not silently improve assertions and then claim before/after evaluator equivalence.

Trigger queries remain the current 32 balanced entries, with byte-preserved query text and labels. Use three named evidence categories:

| Category | What it can establish | What it cannot establish |
| --- | --- | --- |
| Dataset conformance | Valid labels, unique normalized queries, supported schema and unchanged projection | Actual discovery, activation or answer quality |
| Selection diagnostic | What a classifier or model says it would select under that diagnostic prompt | A real client's skill loader selected/read the installed skill |
| Host activation experiment | Observed skill discovery/load events for a recorded installed artifact, client and model under the actual user query | General cross-host portability or successful downstream task execution without separate evidence |

For a separately authorized host experiment, retain host/version, provider/model/effort, installed artifact identity, competing installed skills, environment/capability policy, query, load evidence, answer and failed/unknown status. Keep original and held-out query sets distinct and repetitions explicit. An absence of observable load events is unknown unless the host's observation contract establishes otherwise. Loaded-body behavioral evaluation is a separate lane. Description optimization, additional negative examples and threshold changes are not authorized by this migration.

## Proof and exit

Golden fixtures cover both follow-up traces, exact schedule cells and unchanged assertion/label mapping. Negative controls cover a missing second turn, unsupported provider, altered bundle, ambient credential/config injection, wrong or replayed authorization, incomplete grades, a lexical pass with semantic failure, and a reported selection without a host load event. Require zero provider launches for invalid authority or protocol.

After the proposed tests exist:

```powershell
node --test "tests/naming-objects-in-software-engineering/*.test.mjs" "tests/evals/naming-objects-in-software-engineering/*.test.mjs" tests/scripts/evaluation-trigger-contract.test.mjs
```

Run impacted shared conversation/capability/runtime tests, scoped discovery tests and `npm run verify`. No model call is needed for deterministic acceptance. Real behavior and host activation remain named pending experiments until separately authorized and executed.

Exit requires a supported new-run route, honest grading/trigger labels, installed checker characterization and removal of the hardcoded executable path from live execution. Keep any required legacy data reader and all ignored local results untouched. If the new path fails, stop new execution and retain evidence; do not reactivate the bypass as an automatic fallback. Any individually approved legacy diagnostic run is a separate decision, not an undocumented assurance mode.
